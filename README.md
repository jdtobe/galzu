# Herd social prototype

A local, social-only proof of concept for an agent herd. It does not provide external HTTP/TCP agent tools or perform NAS assessment.

Start Ollama separately, install a model that supports the required JSON responses, and run:

```sh
go run ./cmd/galzu
```

Open http://127.0.0.1:8080. The Sessions library lists saved runs with their name, goal preview, status, agent count, and last recorded event time. Choose New session, configure a goal and exactly one leader, and give each agent an installed Ollama model. Names are optional and can be changed later; unnamed runs use a goal preview in the library. The library is paginated, with an explicit Refresh button; activity can change page ordering. You can also open a session by ID from the library.

Search the entire library by session name, goal, or ID and combine it with All/Running/Paused status filtering. Matching uses literal substrings (so `%` and `_` are not wildcards), with SQLite's ASCII case-insensitive matching. Messages, rejected output, and private working memory are not searched. Filters are applied before pagination, persist when returning from an open session within the page, and reset pagination when changed. Clear filters restores the full library. The API accepts `q`, `status` (`running` or `paused`, omitted for all), and `offset` on `GET /api/sessions`.

Paused sessions have a small red trash can on their library card. The first click arms deletion (inverted colors, a question mark, and an explicit permanence warning); the second click confirms. Clicking elsewhere, pressing Escape, refreshing, or navigating cancels an armed confirmation. Confirmation permanently removes the run's agents, conversation (including private messages and thinking), working memory, checkpoints, settings, events, and failure history in one transaction. Any unfinished inference is canceled and its result discarded. Running sessions must be paused first; opening another browser tab does not bypass this requirement. Other tabs viewing a deleted run return to the library. There is no undo. Deletion is not secure erasure: SQLite free pages, filesystem snapshots, and external backups may retain copies. The API requires `DELETE /api/sessions/{id}` with JSON `{"confirm_id":"the exact session ID"}`.

Completed turns and messages are saved automatically in SQLite; no Save button is required. Opening a session does not resume it, and returning to the library does not pause a running session. Use Pause/Resume explicitly. Pause stops new scheduling but is not a frozen, portable snapshot of in-flight model generation. Unsent message drafts survive switching sessions within the current page, but not a browser reload. Portable export/import and branching are not implemented yet. Restarted sessions begin paused; after resuming, agents process messages not yet handled. Replies and per-agent checkpoints are saved together; an inference interrupted before its reply is saved can be retried. Existing agents without checkpoints start at their history boundary when the database is upgraded.

The session setup checkbox requests thinking for all agents from their first turn; it is off by default. Individual agent checkboxes can be changed during a session and apply to subsequent inference requests. If Ollama and the model return a separate thinking field, it appears in an expandable panel on emitted messages and is saved in SQLite; it is not fed back into agent prompts. Thinking from a rest response is not displayed. Support varies by model, and thinking is not necessarily a complete or reliable explanation. The chat follows new messages when scrolled to the bottom and preserves position when reading earlier messages.

The conversation-first workspace has a compact agent roster, a central conversation and composer, and a selected-agent inspector. Select an agent to see its model, thinking setting, retry controls, last completed turn, timing/prompt diagnostics, and persisted failure history. Details open as a side drawer on narrower screens; on phones the roster becomes a horizontal strip. All activity/Public/Direct messages are display filters, not privacy boundaries: the operator can still see private exchanges. Private messages and help requests are labeled, and human-message delivery details expand to show individual recipients. Activity-only updates avoid rebuilding an unchanged conversation. No working-memory freshness indicator is shown because it is not currently exposed by the snapshot API.

Agent activity shows idle, queued (waiting for a harness concurrency slot), or inference (request sent to Ollama). Agents also receive an advisory snapshot of peer activity in their roster, not a guarantee of availability. Queue time includes any pause before the request starts; inference time is the elapsed request time, including any internal Ollama queueing. Prompt size is the sum of UTF-8 content bytes, not tokens. Reused prefix is the share of this prompt that is byte-identical to the agent's previous prompt, an upper bound on Ollama's KV-cache reuse; Tokens re-evaluated is what Ollama actually evaluated, which is lower when its cache was still warm and higher when another agent used the same slot. Values describe the current or most recent turn, are held in memory, and reset on restart; they do not prove hardware utilization or actual parallel generation.

Each agent is asked to return a private working-memory summary with every action, including rest. A nonempty summary of at most 2,048 UTF-8 bytes is saved atomically with the completed turn and checkpoint. If a model omits or oversizes an update, the previous summary is retained but marked stale. Summaries are model-generated, may lose or distort evidence, and are not verified facts; producing them also adds output and inference cost. A summary is not automatically shared with other agents, though a model may choose to reveal information in a message. The operator and anyone with database access can read stored summaries.

Prompts are append-only so the inference server can reuse its KV cache. A fixed preamble carries the session goal, rules, reply protocol, and the agent's ID and role; then a fixed epoch header; then every message after the agent's cut, rendered from immutable message IDs with no names or timestamps. Memory, roster, activity, and corrective feedback are rebuilt in a final turn packet, where changing them cannot disturb the cached prefix. Peer names appear only in that packet, so renaming an agent no longer rewrites its history.

When that prefix exceeds 32 KB, the runner advances a persisted per-agent cut to bring the rendered log back to roughly 16 KB and states in the header that earlier messages are omitted. The cut only moves forward, so the prompt is cold once per compaction and append-only in between; a model reload, protocol change, or context-window error is the other reason for a cold prefix. Older messages remain in SQLite but are neither prompted nor directly searchable, so agents must rely on their notes or ask. No summary is generated at the cut yet.

Options: `-listen` changes the HTTP bind address, `-db` the SQLite path, and `-ollama` the Ollama server URL. The prototype has no authentication; do not expose it to untrusted networks. Agent interactions can continue consuming inference resources until paused.

Agents receive a roster and can broadcast, send direct messages, or request help publicly or from one agent. Direct content is included only in the sender's and recipient's contexts; other agents see an activity notice, not the content, when they next process recent history. The human operator can see private content in the chat and database. Invalid or unavailable recipients are rejected and retried with host feedback. These are lightweight messages, not tracked assignments or guaranteed replies; models may not reliably use the available actions. Any agent can put a binary question to the herd (`propose`) and vote on an open one (`vote`). A vote closes when every agent has voted or after ten minutes, and passes only on a strict majority of ballots cast, so ties fail; expiry closes a vote with the participation it has, and abstention is absence rather than a no. Ballots can change while the vote is open, and each carries its reasoning. The harness closes and announces votes, so an agent cannot award itself a result. Questions and ballots are listed at `GET /api/sessions/{id}/proposals`. A helper can move no confidence in the leader with `propose` and `kind: "confidence"`; the leader does not vote on its own removal, and a leader cannot move no confidence in itself, since that is a resignation. A passed motion demotes the leader and opens an election automatically. In an election, every agent may stand and the ballot names a candidate; the most ballots wins, a tie leaves the herd without a leader rather than letting the harness choose, and the harness enforces one leader at a time. Resignation, apoptosis, idle reflection, approvals, external tools, and curated memory are later milestones. Agents that exhaust recovery attempts appear as errors; use Retry agent to retry from the last checkpoint after addressing the cause. When more than one agent has failed, the roster offers Retry all failed, which restarts every agent left in error at once and leaves agents waiting on an automatic retry to their own schedule. Retrying while the herd is paused waits for resume.

Inference failures and invalid model actions receive up to three automatic retries after the initial attempt, with jittered delays of approximately 2, 10, and 30 seconds. Attempts time out after 10 minutes. Retry state and bounded failure history persist across restarts; interrupted in-flight attempts are recorded without consuming a retry; prompts are rebuilt for each attempt, and validation feedback is visible only to the affected agent. The operator can expand failure details, including rejected output that may contain private information. If all attempts fail, the agent needs manual retry and its messages remain pending. Context-window errors recognized from Ollama trigger smaller message batches and a notice that older history is saved; direct historical search is not yet available. Context-limit detection depends on Ollama's error wording and cannot guarantee recognition of every model or server response. The attempt timeout and retry delays are configurable at session creation; an empty retry schedule disables automatic retries. A detected storage failure stops session scheduling in memory; recovery requires an explicit write check and leaves the session paused. Human messages show per-agent progress: processed means included in a completed turn, not necessarily understood or answered; historical delivery from before this feature is unknown.

An optional literal-IP target and minimum request interval can be saved when creating a session, but these settings are not active network access: agents cannot request or execute network tools yet. The internal network primitives are not a complete approval or safety boundary and must not be used for live assessment until that flow is implemented and reviewed. That boundary is specified in `docs/superpowers/specs/2026-11-01-tool-policy.md`, and its gate is now implemented but not reachable: `internal/toolgate` evaluates a request against a session's envelope and records the decision, and `/api/sessions/{id}/scope`, `/arm`, `/disarm`, `/approvals` and `/audit` grant, arm, clear and report it. No agent action reaches the gate yet, so nothing can execute. Arming is refused without a written statement of what counts as lasting damage, a new scope version always lands disarmed, and tool requests and their audit trail deliberately outlive session deletion.

The name and visual design are provisional. Basic UI colors are defined as CSS custom properties to leave room for future branding and themes; there is not yet a theme switcher.

Checks: `go test -race ./...` exercises the Go backend; `node --test internal/server/ui.test.cjs` checks conversation filtering, agent-state labels, and delivery display rules.
